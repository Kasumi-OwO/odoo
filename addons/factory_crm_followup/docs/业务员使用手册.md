# 工厂 CRM 业务员使用手册

## 1. 先理解三个对象

- **工厂客户**：客户主档，保存姓名、电话、微信、地区、买家等级以及历史采购次数和金额。客户主档长期保留。
- **复购商机**：本次要推进的一笔业务。一个客户可以先后产生多笔商机，但同一时间只保留一个活动中的复购商机。
- **活动与跟进记录**：活动回答“下一步何时做什么”；跟进记录回答“何时沟通、说了什么、客户意向和顾虑是什么”。

不要把客户主档当成一次交易，也不要只在聊天软件中保存沟通过程。

## 2. 每日标准工作流

### 第一步：找到今天要联系的客户

进入 **CRM → 销售 → 工厂客户**。

可以使用以下筛选器：

- **我的客户**：负责人是当前业务员的客户；
- **未分配客户**：尚未分配负责人的客户；
- **复购客户**：历史采购次数大于 1；
- 买家等级、省份、采购次数、累计金额和最近采购日期。

业务员学习阶段建议每人先认领 10～20 个客户，不要一次处理数千条数据。打开客户后，将“销售员”设置为自己。

### 第二步：了解客户历史

打开客户的 **工厂客户** 页签，重点查看：

- 买家身份、等级和所在地区；
- 首次和最近采购日期；
- 历史采购次数与累计金额；
- 是否由广告引导、历史需求与联系方式。

原表中存在重复电话和矛盾日期，系统按源数据保留，业务员联系后应在销售资料中补充最新的真实情况。

### 第三步：创建复购商机

点击 **创建/打开复购商机**。

系统会自动：

1. 将商机关联到当前客户；
2. 把当前登录业务员设为负责人；
3. 复制电话、微信、客户类型和采购资料；
4. 创建一个截止日期为当天的“首次客户复购回访”活动；
5. 如果该客户已有活动中的复购商机，则打开原商机，不重复创建。

### 第四步：从活动开始工作

进入 **CRM → 销售 → 我的活动**，按截止日期处理任务。

完成电话、微信或邮件联系后：

1. 标记当前活动完成；
2. 在商机的 **跟进历史** 中新增跟进记录；
3. 填写沟通日期、沟通内容、客户意向、客户顾虑和下次跟进日期；
4. 如果仍需联系，立即安排下一项活动。

原则是：每个活动中的商机都必须有明确的下一步和日期。

### 第五步：推进销售阶段

进入 **CRM → 销售 → 我的管道**，按实际进展移动商机：

1. 已加微信建立联系；
2. 需求已明确；
3. 已报价；
4. 已寄样；
5. 已成交；
6. 已丢失或暂不跟进。

不要为了报表好看提前移动阶段。寄样时填写快递单号和样品状态；成交后标记“已赢得”；客户明确拒绝或长期无效时标记“丢失”并填写原因。

## 3. 新业务员的 30 分钟练习

管理员或主管先给业务员分配 3 个测试客户，然后让业务员依次完成：

1. 登录并打开“我的客户”；
2. 查看一个客户的采购历史；
3. 创建复购商机；
4. 在“我的活动”中找到首次回访任务；
5. 填写一条模拟跟进记录并安排明天再次联系；
6. 把商机从“已联系”移动到“需求已明确”；
7. 在“我的管道”中确认商机仍有下一项活动。

练习数据不要标记成交；完成后由主管将练习商机归档或标记丢失。

## 4. 主管的初始化工作

当前系统使用无邮箱开户模式，详细步骤见[无邮箱用户管理](无邮箱用户管理.md)。

1. 在设置中为员工创建内部用户；
2. 授予 CRM 的“用户：仅自己的文档”权限，主管使用“管理员/所有文档”权限；
3. 建立销售团队并添加业务员；
4. 先分配小批客户，观察一周后再扩大范围；
5. 每周检查逾期活动、无下一步商机、各阶段停留情况及跟进记录质量。

客户分配可以按省份、买家等级、复购次数或历史金额进行。不要只按总数量平均分配，因为客户价值和资料完整度差异很大。

## 5. 常见问题

### 客户和商机有什么区别？

客户是长期档案；商机是一次正在推进的销售机会。客户不会因为一次失败而删除。

### 为什么看不到原来的 14,991 条线索？

原始导入线索已经关联客户后归档，避免污染日常线索池。数据没有删除，完整历史字段已迁移到工厂客户。

### 点击按钮会不会重复创建商机？

同一客户已有活动中的复购商机时，按钮只会打开现有商机。商机成交、丢失或归档后，才可以开始下一轮复购机会。

### 没有微信或客户类型能否保存？

可以。系统会将资料标记为不完整，但不会阻止业务员先记录真实沟通结果。

### 电话或昵称重复怎么办？

不要直接合并。先核对地址、企业名称、采购历史等信息，确认是同一客户后再由主管处理。

## 6. 使用纪律

- 不删除历史客户或跟进记录；
- 不在备注中保存账号密码等敏感信息；
- 每次沟通都写跟进记录；
- 每个活动商机都设置下一步日期；
- 客户分配和批量合并由主管执行；
- 发现源数据错误时补充最新资料，不覆盖无法确认的历史事实。
